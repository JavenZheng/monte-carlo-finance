## 一、你上节课卡在哪里

第 01 课你用六张便利贴演了十轮，得到一个和邻座不一样的答案。原因不是你做错了，是十遍太少：这件事要演到几万遍，那个数才稳住。

人手演不了几万遍。机器可以，而且只要几秒。

所以这门课接下来要交给你的，是一台能替你演纸片的机器。但在那之前，有一件事必须先解决：**你得会跟它说话。**

这节课不讲金融，不讲概率，只解决这一件事。走到最后，你会拥有一个中午就能用上的东西——一个改一个数就重算的账格子。它同时也是这门课后面所有模拟的地基：以后你写的每一个蒙特卡洛，形状都和今天这二十分钟一样。

## 二、先打开一个格子

打开浏览器，访问 [https://jupyter.org/try](https://jupyter.org/try)。这是 Jupyter 官方的免安装入口，代码直接跑在你自己的浏览器里，不用注册、不用登录、不用下载。

等十几秒，你会看到一个空页面，中间有一行可以打字的区域。那个区域叫**单元格**（cell）。你写一行字，按一下 `Shift` 和 `Enter`，它就替你执行，并把结果显示在下面。

先试这一行，敲进去然后按 `Shift + Enter`：

```
print(38 + 42 + 29)
```

看到 `109` 出现在下面了吗。到这里你就已经会写代码了。这门课剩下的部分只是把这件事做得更值。

**一件要提醒的事**：这个免安装版本没有地方帮你存东西，刷新页面就没了。所以每写完一段能跑的东西，先复制一份到手机备忘录或者一个文档里。嫌麻烦的话，另一条路是 [Google Colab](https://colab.research.google.com/)，它能存到你的云端，但需要一个 Google 账号。今天先用免安装的，等你能跑东西了再说存档的事。

## 三、第一行代码，和它为什么还不值

`print(38 + 42 + 29)` 得 109。这就是你三天午餐花的钱。

你大概会想：这事我用手机计算器更快。电脑的价值在哪？

价值不在它算得快，在它**记得住你说过的话**。三行手写的数字，改成电脑里三个起了名字的数之后，你可以随时换其中一个、让它把所有结论重算一遍。计算器不会替你重算，它只答你按的那一下。

这句话是整节课的枢纽。我们下一节把它做出来。

## 四、变量：给一个数起个名字，是一张便利贴

先回想第 01 课那六张便利贴：一张上面画个点，其余留白。**便利贴的作用是：你在一上面写了什么，它就代表什么。**

代码里的变量就是这样一张便利贴。你把一个数贴在上面，以后叫这个名字，就能拿到那个数：

```python
lunch = 41
```

这一行不会显示任何东西，因为它不是在问问题，是在贴便利贴。名字叫什么都行，`lunch`、`w`、`今天午饭`——Python 都认，但只有前两种你不会以后看不懂。等号 `=` 在这里不是"相等"，是"把右边的数贴到左边这个名字下面"。

贴上去之后，你可以用它：

```python
lunch = 41
print(lunch * 22)
```

输出 902。这里 `*` 是乘号。

现在做一件你在计算器上做不到的事：把 `41` 改成 `38`，重跑。`print` 那一行你一个字都没动，可它的答案自己变了，从 902 变成 836。

**这就是全部的意义。** 你在纸上写的"41 × 22"，改一个数要把整行重算；你给它起了名字，就只需要改贴便利贴那一次。数字多的时候，差别是"改一处"和"从头再来"。

## 五、中午那件真正让你纠结的事

快到下午一点，你在外卖 App 前停住了。一份饭 41 块，你想再加一杯 8 块的咖啡，但你对自己说过这个月午餐别超一千块。

你心里其实有三个问题，全都是同一个问题的不同说法：我这样吃下去，月底是多少？离我给自己划的线还有多远？如果还剩空间，能不能加一杯？

把这三个问题写成电脑能替你回答的样子，就是这节课的成品。整段贴进单元格，按 `Shift + Enter`：

```python
elapsed_days = 11      # 这个月已经过了几个工作日
spent = 449            # 这些天午餐一共花了多少
workdays_left = 11     # 这个月还剩几个工作日
budget = 1000          # 你给自己的整月午餐预算
coffee = 8             # 你纠结的那件小事

daily = spent / elapsed_days
month_end = daily * (elapsed_days + workdays_left)
daily_cap = (budget - spent) / workdays_left
headroom = daily_cap - daily

print(f"过了 {elapsed_days} 个工作日，花了 {spent}，平均每天 {daily:.1f}")
print(f"照这个速度，月底落在 {month_end:.0f}，而你的预算是 {budget}")
print(f"剩下的 {workdays_left} 天，每天最多能花 {daily_cap:.1f}")
print(f"也就是比现在宽出 {headroom:.1f} —— 你想要的那杯是 {coffee}")
```

我这台机器上跑出来是：

```
过了 11 个工作日，花了 449，平均每天 40.8
照这个速度，月底落在 898，而你的预算是 1000
剩下的 11 天，每天最多能花 50.1
也就是比现在宽出 9.3 —— 你想要的那杯是 8
```

逐段说清它在干什么。

前面五行是贴便利贴，把你知道的五个事实各起一个名字。数字后面的 `#` 是注释：井号往后的这一行电脑不看，是写给你自己看的。中文注释随便写，这正是它有用的地方。

中间四行是真正的算式，`/` 是除号。`daily` 是你现在的日均；`month_end` 是按这个日均推到这个月所有工作日的总额；`daily_cap` 是预算扣掉已花的，再摊到剩下的天数上；`headroom` 是这两个的差，也就是**你每天还宽出多少钱**。

最后四行把算出来的数塞进句子。句子前面那个 `f` 是在告诉 Python：这串引号里夹着的 `{...}` 不是文字，是要它算出来再填进去的洞。`{daily:.1f}` 里的 `.1f` 是"显示成一位小数"，不然你会看到 40.81818181818182。

然后回到你最开始那个问题。宽出 9.3，你想加的是 8。今天这杯咖啡，在你自己划的那条线以内。

顺便，注意它替你顺手做掉了一件你本来不会做的事：它把"能不能加一杯"变成了"还剩几天、摊下来每天多少"。你原来只会凭感觉说好险或者没事。

## 六、报错了，先别关掉

上面那段一定会在某些人手里变红。这不是你笨，是这几行里有中文标点、有大写小写、有括号，只要一个字符不对，Python 就拒绝执行。它拒绝的时候会说清楚哪儿不对，你只需要知道去哪儿看。

规则很简单：**错误信息的最后一行是结论，倒数第二行告诉你它死在哪一行。** 四种最常见的，我把原文一字不改贴给你。

少一个右括号：

```
SyntaxError: '(' was never closed
```

名字打错了，比如把 `lunch` 写成 `Lunch`（大写）：

```
NameError: name 'Lunch' is not defined. Did you mean: 'lunch'?
```

它甚至会把你想写的那个名字猜出来。Python 分得清大小写，`lunch` 和 `Lunch` 是两张不同的便利贴——这是新手和电脑之间最常发生的一次误会。

用了中文引号或中文括号：

```
SyntaxError: invalid character '“' (U+201C)
```

这个错几乎每个人都会撞一次，因为中文键盘的引号和代码需要的引号长得几乎一样。修法是把那一句的引号删掉重打，并且把输入法切到英文。**从这一段起，代码只在全英文输入法下打。** 引号、括号、逗号、冒号、等号，中文的那一套电脑全都不认。

算出来要除以零，比如你一时手滑把 `elapsed_days` 填成 0：

```
ZeroDivisionError: division by zero
```

这一条其实是救你的。用 0 天去推一个月的花费，会得到一个荒谬的结论还看起来理直气壮；它宁可停下来不给你答案。

还有一种你以后会遇到：把数字写进了引号，`spent = "449"`。Python 不报错在贴便利贴那行，而是等到要除的时候才说：

```
TypeError: unsupported operand type(s) for /: 'str' and 'int'
```

意思是它手里那个 449 是一段文字，不是一个数。文字不能除以天数。**带引号的数字是文字**，这条会跟你一辈子。

看到红字的时候，先读最后一行，再对行号。你不需要读懂整段英文——绝大多数时候，最后一行的第一个词就是答案的类型：`SyntaxError` 是拼写不对，`NameError` 是名字不存在，`ZeroDivisionError` 是除以零。

## 七、今晚就换成你自己的数

这段代码值得你留下来的理由，不是它教你写了变量，是它以后每个月月底都会替你回答一次"我这个月是不是超了"。

把最上面五个数字换成你自己的：已经过了几个工作日、这几天的午餐实际花了多少、还剩几个工作日、你给自己的线、你那件想加的小事。咖啡换成地铁、换成一顿聚餐、换成任何你想在月中判断一次的事都行——只要它是按天发生的、你记了账的。

文件在仓库里：[code/lesson02_lunch_budget.py](../../code/lesson02_lunch_budget.py)。不想开浏览器也可以本地跑：

```bash
python3 code/lesson02_lunch_budget.py
```

跑之前先做一件事：把 `budget` 从 1000 改成 800，然后看输出的哪一句变了、变成什么。

我跑过，答案是第三、四行变成"每天最多能花 31.9""比现在宽出 -8.9"，而第一、二行一个字没动。**负数的宽出**就是那句话的意思：照现在这个吃法，你不但加不了那杯咖啡，每天还得往回退 8.9 块才不超线。

这就是这门课一直想要你习惯的动作：**改一个假设，看结论怎么跟着动。** 你今天在午餐账上做的这件事，和后面在原书里改一个波动率、看期权价格怎么变，是同一个动作，没有高低之分。

## 八、为什么要为这些花一整节课

因为从这里到那本书，中间所有东西都是今天这个形状。

以后你会写一个模拟，算一支股票明年值多少钱。那个程序的开头也长这样：贴七八张便利贴——起始价、波动率、期限、步数、要演多少遍；中间是一串算式；最后是几个结论。你想知道另一个假设下的结果，就动那张贴纸，重跑。

原书里每一张表格、每一个数字，背后都是一次"改了哪个假设、跑了多少遍"。你今天下午已经会读这个结构了：结论不属于现实，属于那五个数。数改了，结论必须跟着改。这一点第 01 课第六节已经提醒过你一次（你那个杯子搭错了世界，演多少遍都是精确地错），今天它变成了一件你能亲手操作的事。

所以这节课给的第一个能带走的东西，是一个账格子。第二个是：**你现在敢对一个数字负责了**——因为你能说出它是从哪几个假设长出来的。

## 九、练习

**一。** 把你自己的真实数字填进那五行便利贴，跑一次，然后把结果的那句"每天最多能花多少"截图存下来。这个月底你会回来看它。

**二。** 你把 `budget` 改成 700 重跑，四行输出里哪几行变了？"宽出"那个数现在是正是负？按它说的，你接下来每天该往哪个方向调？

**三。** 你同事说他"每天午餐绝不超过 50"。用这一节的算法，你要问他哪两个数才能验证？只有他"这个月一共花了 550"够不够？

**四。** 你把 `coffee = 8` 改成 `coffee = "8"`（带引号）重跑。它在哪一行报错，还是根本没报错？为什么？

### 答案

**一。** 这一步没有对错，它练的是"我手上的数我自己填过"。你会在跑完的那一刻发现一件事：`elapsed_days` 和 `workdays_left` 这两个数你是查了一下日历才知道的——大多数人的焦虑不是来自数据，来自他根本没有那两个数。

**二。** `budget` 只出现在第三、四行，所以前两句一字不动，后两句变成"每天最多能花 22.8""比现在宽出 -18.0"。是负数，而且是比 800 那次更大的负数。要满足 700，你每天的午餐得压到 22.8 以内——而这个数低于你现在任何一顿的价格，说明这条线本来就不是给你定的。这就是把感觉翻译成数字的价值：你可以直接决定"那我把线改到 900，或者改吃法"，而不是月底才发现。

**三。** 要问他两个数：**这些天总共花了多少**、**这几天是几个工作日**。只有 550 不够，因为 550 摊在 11 天上是每天 50，摊在 22 天上是每天 25，两个结论相反。这个差别以后你会在金融里再见到很多次：一个总数，没有对应的天数或次数，什么也说明不了。

**四。** 它不在你改的那一行报错——贴便利贴什么都不会算，Python 那时还不知道你要干什么。它会在 `headroom = daily_cap - coffee` 那一行炸掉，因为数减去文字是不成立的运算，`TypeError`。**报错的行不等于你写错的行**，这是读错误信息时最反直觉的一条。

## 进阶框（可跳过，不影响下一课）

**`.py` 文件和单元格有什么区别。** 你在浏览器里敲的是一块块单元格，敲一块跑一块，中间贴上去的便利贴会一直留着；仓库 `code/` 里的 `.py` 文件是一整篇，从第一行跑到最后一行，跑完就结束。做实验用单元格，做完要留给别人用就存成 `.py`。这门课前面的课给的都是 `.py`，你完全可以把它们整段粘回单元格跑。

**为什么 `449 / 11` 是 40.81818181818182。** 电脑存小数用的是二进制分数近似，很多你在十进制里觉得简单的数（比如 0.1）在它那儿存不准。影响是：不要用 `==` 去比两个算出来的小数是不是严格相等，要看差的绝对值是不是足够小。你后面会碰到几次，先记住这条。显示上的 `.1f` 只是四舍五入给你看，它没有改变那个数本身。

**`{daily:.1f}` 这套写法叫 f-string**，是"把算出来的东西嵌进一句话"的标准做法。冒号后面是显示规格：`.2f` 两位小数，`.0f` 不带小数。它只影响说出来的样子，不影响值。

**整除和余数。** `7 / 2` 得 3.5；`7 // 2` 得 3（除掉小数部分）；`7 % 2` 得 1（剩下的）。以后你要"每 20 条打包一批""最后一天不满怎么办"这类问题，靠的是这两个符号，现在只需要知道它们存在。

## 备忘卡

本课出现的东西，正式名字在这里。

**便利贴**，正式叫**变量**（variable）：一个名字对应一个值，`名字 = 值` 把它贴上去。**算式**（expression）：任何能算出一个东西的一串，`spent / elapsed_days` 是，`41` 也是。**单元格**（cell）：一次能执行的一块。**注释**（comment）：`#` 往后，给人看不给电脑看。**报错 / 异常**（exception）：电脑拒绝执行时说的话，最后一行是类型。**输入法**：代码里所有标点必须是英文半角。
